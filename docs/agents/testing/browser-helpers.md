# Testing: browser spec helpers

Helpers and launch settings that every browser spec shares. The index is `docs/agents/testing.md`.

- `openTour` (`tests/lib/page.ts`) records how long its `goto` and boot took as a `boot-ms` test annotation. A spec's own `page.goto` isn't measured. A test that calls `openTour` twice has two annotations, which the report adds up; the report's median and total cover annotated tests only, and it says how many. This is the measurement for sharing one booted page per worker (#321, phase 2)
- `tests/boot.spec.ts`'s `slowModel` helper serves the room model from a local server and waits on CDP `Network.dataReceived` for each chunk. That server must answer only `/room.glb`: on the Mac a stray `GET /` sometimes reaches it, and taking it for the model sent later chunks to a dead response, so the wait timed out (a chunk behind, or at 0) in whole-file runs only. The slow-load test needs the whole file to show it: `heavy make browser-light PW_ARGS="tests/boot.spec.ts --repeat-each=5"`
- `waitForCamera` (`tests/lib/page.ts`) asks the scene for a frame before each read (a `pointermove` on `window`, which only the room's redraw hears) and waits for `data-camera` to be written. The scene draws on demand and writes `data-camera` per drawn frame, so a plain read can't tell a camera at rest from one whose next frame is late: slow frames under load gave two equal reads mid-ease (#330). Read the camera at rest with it, not with `waitUntilStill` over `data-camera`. `tests/wait-until-still.spec.ts` delays every frame to check it
- `playwright.config.ts` launches Chromium with `--host-resolver-rules=MAP mediasafe.space ~NOTFOUND` (merged with the CI llvmpipe launch options), so MediaSafe's host never resolves in any spec and **no browser spec calls production MediaSafe** (#369). It is a launch flag because many specs open the site without `openTour` (`openStation`, `tests/stepping.spec.ts` and others do their own `page.goto`). `playwright.screenshots.config.ts` has the same flag, so the screenshots job never calls it either (and Off the keyboard's screenshot shows the bullet alone), and `scripts/playwright-config.test.mjs` (in `npm test`) checks both configs carry it, with and without llvmpipe. A spec's own `page.route` still serves a fake answer, since Playwright answers a routed request before any lookup. A spec that tests the Last watched line serves a fake answer for `LAST_WATCHED_URL` and sends `Access-Control-Allow-Origin: *` and `Content-Type: text/plain; charset=utf-8` with it: the call is cross-origin, and without the header the browser refuses it, so a "hidden on failure" test would pass for the wrong reason
- One spec in the session: `heavy npx playwright test tests/<spec> --workers=1`
